## Data, authorization, realtime, and media architecture discovered

- Supabase is the active configured backend abstraction. The migration directory contains the schema, RLS policies, RPCs, storage policies, relational cutovers, and Realtime-topic authorization changes. It includes native typed records for posts, friendships, conversations, verdicts, stories, dares, challenges, birthday rooms, and auxiliary social features.
- Feed, comments, reactions, dares, truth interactions, challenges, messaging, stories, and room features subscribe to Supabase Postgres changes or private/presence channels. The optimized feed now keeps a scoped `posts` Postgres listener and coalesces authorized API refreshes after changes; one bounded no-refresh A→B sample was observed, while a 20-run timing series remains unexecuted.
- Media uses Supabase Storage, content validation/client-side image preparation, non-upserting object uploads, and signed URLs. Persisted Supabase Storage links are refreshed server-side when near expiry so private media remains viewable after the original one-hour link expires. No active Cloudinary or Cloudflare R2 integration was found in the scanned source/configuration; this is a discrepancy from the requested brief and needs product-owner confirmation before such testing is claimed.
- The project contains Jest unit tests; no pre-existing Playwright configuration or E2E suite was found before this audit.
