DARE INTERPRETATION (DESIGN CHOICES, NOT MEASURED COMPETITOR SPECS)
- Content-sized text bubbles capped at 80% of conversation width; 16px text,
  1.4 line height, 10px vertical / 14px horizontal padding, 20px outer corners.
- Consecutive plain messages from the same sender less than five minutes apart
  form a visual group. Joined corners use 6px radii. Break grouping at cards,
  media, replies, system events and pending/failed states as applicable.
- Circle sender names appear at incoming group starts, timestamps at group ends.
  Pending/failed messages keep their own status. Own messages need no repeated
  'You'. Keyboard and long-press actions remain available on grouped messages.
- Preserve Circle's purple accent. Sender identity accents come deterministically
  from FriendCircleScreen's green, rose, sky, purple, yellow, mint, blue and pink
  palette. Incoming text surfaces stay neutral; outgoing bubbles are tinted.
- DMs default to Dare green with distinct incoming charcoal surfaces. Existing
  app theme overrides and mood panels remain intact.
- Compact header: 36px avatar, 44px action targets, 56px content height plus safe
  area. A Lucide menu icon replaces the previously corrupted text glyph.
- Existing inline replies: 3px accent rail, 12px author, 13px two-line excerpt.
  Photo fallback text and original reply data/actions remain unchanged.
- Composer uses 16px input, 44px minimum controls, capped multiline growth and
  safe-area padding. No fake buttons or new reply backend in Circle chat.
- One low-opacity static background wash. Glass belongs to header/composer,
  not every message. Short 140-160ms message feedback and 200ms Circle sheet.
  Reduced-motion removes message entrance and press movement.

IMPLEMENTATION BOUNDARY
Shared CSS presentation tokens and a pure grouping helper. Existing stores,
services, Supabase tables, subscriptions, pagination, uploads and notification
rules are unchanged. Circle interaction cards retain their category colours,
status display, source message and navigation.

MOBILE KEYBOARD / LOADING CORRECTION
- Removed the Circle demoMessages fallback entirely. Previously it rendered
  temporary messages while actual history was loading, causing the preview flash.
- Both real chat screens now use a shared callback-ref viewport controller for
  VisualViewport.height and offsetTop, including resize, pan and focus events.
  The scroll feed shrinks; composer/header do not. Keyboard-open bottom padding
  avoids adding a second safe-area gap. Controller reattaches after nested screens.
- Removed the scrolling/animated overlay wrapper specifically for these two chat
  screens so it cannot add a second offset or clipped outer scroll area.
- Header refined with a 40px identity/avatar, 44px actions, subtle accent surface,
  compact title/status hierarchy and connection status beside the Circle subtitle.
- Evidence: https://developer.mozilla.org/en-US/docs/Web/API/VisualViewport
  https://developer.chrome.com/blog/viewport-resize-behavior/
  Keyboard may shrink visual viewport without changing layout viewport; merely
  resizing the browser window was insufficient testing for this defect.
- tests/qa/mobile-chat-keyboard.spec.ts uses Pixel 7 and iPhone 13 device settings
  (mobile user agent, touch and device scale) in Chromium. It keeps innerHeight
  unchanged while simulating VisualViewport heights 400/350/430 and offsetTop 48.
  Assertions check input/composer bounds, keyboard-close restoration, no loading
  demo messages, and returning from Games. This is not actual iOS Safari or a
  physical OS keyboard test. Screenshots: .tmp/chat-keyboard/.
